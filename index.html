02 Projects

A selection of the modeling problems behind those dashboards — the kind that don't show up on the report canvas, only in whether the numbers are right.

Utility Allocation Engine
DAX + Power Query
When two brand counters were physically merged at a hub, gas/water/electricity costs needed splitting by actual sales share, not a flat 50/50. Built a sales-weighted split off a brandwise_split JSON column, with parallel Power Query and pure-DAX (CALCULATE + REMOVEFILTERS + USERELATIONSHIP) approaches.
Hub-Level P&L Matrix
SWITCH · Matrix
A 40-metric P&L matrix driven by a disconnected metrics table and a single SWITCH measure. Traced a stubborn "hub row won't disappear" bug to FORMAT(BLANK()) silently returning "0" instead of a true blank — fixed by wrapping every FORMAT call in an ISBLANK guard.
DimHub / DimBrand Consolidation
ADDCOLUMNS
Calculated dimension tables that unify hub and brand identity across Swiggy, Zomato, and the Kitchens@ App funnel — each platform with its own ID space — using ADDCOLUMNS and LOOKUPVALUE so downstream measures never have to know which source a row came from.
Automated Wastage Alerting
Power Automate
A DAX query (SUMMARIZECOLUMNS + a "not entered" flag measure) feeding a Power Automate flow that sends each hub manager a single consolidated email when wastage data goes missing, instead of every manager checking manually.
Page-Level RLS
ISINROLE
Role-based page visibility using ISINROLE() DAX expressions, with defined roles, tested via "View As Roles," and published through Service — including catching the gotcha where a user in no role sees a fully blank report.
DimDate, Built by DAX
Calculated Table
A calculated date dimension unioning date columns from seven source tables across two schemas, with a dynamic cutoff at TODAY()-1 — later ported to Power Query M with List.Transform and a negative-serial sort column for correct chronological ordering.
